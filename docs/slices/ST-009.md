# ARCUS Story Specification: ST-009

## Story Metadata
- **Story ID:** ST-009
- **Story Title:** Spatial Map: GPS Sample Fetching and Fog of War Overlay
- **Epic:** Spatial Explorations and Visual Mapping
- **App Name:** step-tracker
- **Target Local Environment:** http://localhost:1981
- **Primary Test Target:** Ingestion of com.google.location.sample GPS coordinates from Google Fit, Leaflet.js map rendering, and dynamic path-clearing Fog of War shroud overlay.

---

## User Story Statement
> **As a** user who tracks outdoor walks with a GPS-enabled wearable or phone,  
> **I want** my recorded GPS paths rendered on an interactive map with a Fog of War shroud that clears along my walked routes,  
> **So that** I can gamify my physical movement and visually explore how much of my local geographic area I have uncovered.

---

## Context and Business Value
Raw step counts capture volume, but spatial data captures exploration. By pulling GPS coordinate samples from Google Fit and layering a Fog of War canvas shroud over an interactive map, walking turns into a world-discovery experience. Areas walked clear the shroud permanently, giving users visual satisfaction and encouraging them to explore new neighborhood streets.

---

## Scope of Work

1. **Google Fit Location REST API Fetcher:**
    - Extend the sync engine to query Google Fit dataset API for data type `com.google.location.sample`.
    - Parse coordinate payloads extracting latitude, longitude, elevation, and epoch timestamps.
    - Filter out invalid or low-accuracy GPS points (horizontal accuracy threshold > 50 meters discarded).

2. **GPS Coordinate Persistence:**
    - Store array of normalized GPS point objects in the Dexie.js `daily_records` object store under attribute `location_samples`.
    - Optimize coordinate storage density by applying standard point reduction (Ramer-Douglas-Peucker algorithm) to remove redundant collinear points and minimize IndexedDB storage footprint.

3. **Leaflet.js Map Shell Setup:**
    - Initialize an interactive Leaflet.js map container on the Spatial Map tab.
    - Render open-source base map tiles (OpenStreetMap) with zoom, pan, and tile caching capabilities.
    - Set initial map view bounds based on the centroid of historical GPS coordinates (or fallback to default location if no GPS records exist).

4. **Fog of War Shroud Layer Engine:**
    - Implement a custom HTML5 Canvas overlay layer attached to Leaflet map view.
    - Draw a semi-transparent dark shroud (e.g. 80% opacity dark grey/black) across the entire visible map viewport.
    - Iterate through stored historical GPS coordinate paths and apply composite operations (`destination-out`) to carve transparent "cleared" circular radius paths (default: 30-meter clearing radius) along logged walking lines.

5. **World Explored Percentage Badge:**
    - Calculate an exploration metric based on cleared grid tiles within the user's primary bounding box region.
    - Render a high-contrast badge on the map view displaying "World Explored %" (for example: "0.42% of Home Region Explored").

6. **Documentation Updates:**
    - Update repository documentation explaining GPS location syncing, Leaflet map integration, Fog of War shroud rendering rules, and coordinate privacy safeguards.

## Technical Notes and Schemas

### Location Sample Data Schema Addition (`daily_records`)

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `location_samples` | Array of Objects | `[{ lat: 28.6139, lng: 77.2090, accuracy: 8.5, timestamp: 1786270000000 }]` |

### Fog of War Rendering Parameters
- **Base Shroud Style:** `rgba(20, 24, 33, 0.82)`
- **Clearing Radius:** 30 meters at Zoom Level 15 (scales dynamically with map zoom level).
- **Composite Mode:** `globalCompositeOperation = 'destination-out'` to erase dark canvas mask along path polylines.

## Acceptance Criteria (Definition of Done)

### Scenario 1: Syncing and Storing GPS Data
- **Given** an authenticated session with Google Fit location permissions,
- **When** the step sync engine executes,
- **Then** `com.google.location.sample` coordinate arrays are fetched, simplified, and stored in `daily_records` under `location_samples`.

### Scenario 2: Rendering Map and Fog of War Shroud
- **Given** stored location samples in Dexie.js,
- **When** the user navigates to the Spatial Map tab,
- **Then** a Leaflet map initializes, centered over the walking region,
- **And** a dark Fog of War canvas shroud overlays the map, leaving clear transparent pathways along logged GPS walks.

### Scenario 3: Graceful Handling of Days Without GPS
- **Given** a user who walked indoors or without GPS enabled on a specific date,
- **When** viewing the Spatial Map,
- **Then** the application handles empty `location_samples` arrays gracefully without throwing errors or breaking map interactions.

### Scenario 4: Technical Documentation Update
- **Given** completion of the Fog of War spatial mapping module,
- **When** reviewing repository documentation,
- **Then** GPS data ingestion, Leaflet map configuration, and Fog of War rendering mechanics are accurately documented.
