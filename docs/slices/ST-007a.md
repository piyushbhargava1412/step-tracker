# ARCUS Story Specification: ST-007a

## Story Metadata
- **Story ID:** ST-007a
- **Story Title:** Parameterized Goal Lens & Tolerance Streak Engine Refactor
- **Epic:** Goal Tracking and Progress Monitoring
- **App Name:** step-tracker
- **Target Local Environment:** http://localhost:1981
- **Primary Test Target:** Refactoring existing codebase (ST-001 through ST-008) to remove historical goal locking and replace it with a parameterized step-goal lens, 3-tier tolerance streak engine (100%, 95%, 90%), and isolated Search Lab query context.

---

## User Story Statement
> **As a** health-conscious user inspecting my step history,  
> **I want** to dynamically apply step-based goal targets (5k, 7.5k, 10k, 15k steps) across my entire dataset and view my strict and tolerance-based streaks,  
> **So that** I can analyze my consistency under different commitment thresholds without managing historical goal states.

---

## Context and Business Value
Earlier implementations (ST-003, ST-004, ST-005) relied on distance-based goals (km) and a complex "Effective Date Lock" state model. Step counts are the true immutable unit of movement, and distance fluctuates across devices. Furthermore, locking goals to historical dates creates unnecessary schema overhead and prevents dynamic exploration.

This story refactors the application core across Stories 1 to 8:
1. Strips out Effective Date Lock and distance-based goal tracking.
2. Standardizes goals around discrete step targets (5,000 / 7,500 / 10,000 / 15,000 steps).
3. Replaces static streak calculations with a dynamic Parameterized Tolerance Engine (Actual 100%, 95% Allowance, 90% Allowance).
4. Ensures the Search Lab operates as a strictly decoupled, isolated query tool.

---

## Scope of Work

1. **Goal Schema Refactoring & Schema Simplification:**
    - Purge any per-date goal history tracking or "Effective Date Lock" attributes from `settings` and `daily_records` stores in Dexie.js.
    - Update `settings` store to retain only a single active UI goal preference: `active_step_goal` (options restricted to integer values: `5000`, `7500`, `10000`, `15000`; default: `10000`).

2. **Dashboard UI Refactoring (ST-003 Alignment):**
    - Replace distance-based goal controls with a Step Target Selector dropdown offering strictly: 5,000 steps, 7,500 steps, 10,000 steps, and 15,000 steps.
    - Update Today's Progress Card to evaluate today's `effective_steps` directly against the selected step target.
    - Remove all references to "Effective Date Lock" badges, distance goal conversions, or 1km targets across the Dashboard view.

3. **Parameterized Tolerance Streak Engine (ST-004 Refactor):**
    - Implement a backward-traversing streak calculation algorithm that accepts any target step threshold $S_{target} \in \{5000, 7500, 10000, 15000\}$ and computes 3 simultaneous streak metrics starting from current date (or yesterday if today is in-progress):
        - **Actual Streak (100% Strict):** Continuous days meeting or exceeding $S_{target}$. Terminated on the first day where `effective_steps` $< S_{target}$.
        - **95% Compliance Streak (1 miss per 20 days allowance):** Continuous backward window permitting 1 grace miss for every 20 days evaluated.
        - **90% Compliance Streak (1 miss per 10 days allowance):** Continuous backward window permitting 1 grace miss for every 10 days evaluated.
    - Render these 3 metrics prominently in the Active Streak section of the Dashboard.

4. **Dynamic Calendar Heatmap Re-alignment (ST-005 Refactor):**
    - Re-align monthly calendar grid tile color classifications to evaluate historical days dynamically against the active Dashboard step target selected in Scope 2.
    - Ensure changing the Dashboard step goal target dropdown instantly re-renders monthly calendar tile states without requiring page reloads or database updates.

5. **Decoupling Search Lab Context (ST-007 / ST-008 Refactor):**
    - Isolate Search Lab query builder, Near-Miss Detector, and Day-of-Week Slump Analyzer from global Dashboard state.
    - Ensure Search Lab queries evaluate filter criteria using explicit user-entered input parameters inside the Search Lab tab, completely independent of the active Dashboard step target.

6. **Documentation Updates:**
    - Update repository documentation detailing the step-based goal model, allowance window streak formulas, dynamic calendar classification, and isolated Search Lab context.

## Technical Notes and Schemas

### Parameterized Tolerance Streak Engine Algorithms

Given a target step count $S_{target}$ and an ordered array of daily records moving backward from $d = 1$ (yesterday or today if met):

#### 1. Actual Streak (100% Compliance)
- Iterate backward $d = 1, 2, 3, \dots$
- If `effective_steps` $\ge S_{target}$, increment $Streak_{100}$ by 1.
- If `effective_steps` $< S_{target}$, terminate loop and return $Streak_{100}$.

#### 2. Allowance Window Tolerance Algorithm (95% & 90% Streaks)
For a given compliance threshold (95% uses $N = 20$; 90% uses $N = 10$):
- Maintain counters: `days_evaluated` ($d$), `total_misses` ($m$), and `last_valid_streak`.
- Iterate backward $d = 1, 2, 3, \dots$
- If `effective_steps` $< S_{target}$, increment $m$ by 1.
- Calculate maximum allowed misses at evaluation depth $d$:
  $$M_{allowed} = \left\lfloor \frac{d}{N} \right\rfloor$$
- If $m \le M_{allowed}$, update `last_valid_streak` = $d$.
- If $m > M_{allowed}$, terminate loop and return `last_valid_streak`.

## Acceptance Criteria (Definition of Done)

### Scenario 1: Dynamic Parameterized Goal Target Selection
- **Given** an active application session on `http://localhost:1981`,
- **When** the user changes the Dashboard Goal Target dropdown from 10,000 steps to 7,500 steps,
- **Then** Today's Progress Card instantly recalculates completion percentage against 7,500 steps,
- **And** the Active Streak section and Monthly Calendar Heatmap re-evaluate instantly using 7,500 steps without mutating database records.

### Scenario 2: Allowance Window Tolerance Streak Calculation
- **Given** a user step history containing 39 consecutive days where Day 20 had 4,000 steps (1 miss) and all other 38 days had > 10,000 steps,
- **When** evaluating against a 10,000-step goal target,
- **Then** Actual Streak (100%) returns 19 days,
- **And** 95% Tolerance Streak returns 39 days (1 miss permitted for 39 days evaluated since $\lfloor 39/20 \rfloor = 1$),
- **And** 90% Tolerance Streak returns 39 days (1 miss permitted since $\lfloor 39/10 \rfloor = 3$).

### Scenario 3: Complete Decoupling of Search Lab
- **Given** a Dashboard active goal set to 15,000 steps,
- **When** the user switches to Search Lab and runs a query or Near-Miss analysis for 5,000 steps,
- **Then** Search Lab evaluates results strictly against the 5,000 steps input parameter,
- **And** switching back to the Dashboard leaves the 15,000 steps goal active and untouched.

### Scenario 4: Technical Documentation Update
- **Given** completion of the goal and streak refactoring,
- **When** reviewing repository documentation,
- **Then** the parameterized step goal lens, tolerance allowance formulas, and decoupled Search Lab rules are accurately documented.
