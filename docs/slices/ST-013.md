# ARCUS Story Specification: ST-013

## Story Metadata
- **Story ID:** ST-013
- **Story Title:** PWA Service Worker, Cloudflare Pages Deployment Pipeline, and Setup Guide Documentation
- **Epic:** Production Deployment and Application Delivery
- **App Name:** step-tracker
- **Target Environments:** http://localhost:1981 (Local) and https://step-tracker.pages.dev (Production Cloudflare Pages)
- **Primary Test Target:** Progressive Web App (PWA) web manifest installability, offline caching via Service Worker, automated GitHub Actions deployment to Cloudflare Pages, and complete end-user setup documentation.

---

## User Story Statement
> **As a** developer or end-user cloning this repository,  
> **I want** the application packaged as an installable, offline-capable PWA with automated Cloudflare Pages deployment and clear setup documentation,  
> **So that** I can install the app natively on mobile or desktop, host it for free, and guide any Gmail user to set up their own private Google Client ID.

---

## Context and Business Value
This final story transitions `step-tracker` from a local development environment into a production-ready, distributable open-source application. By adding a web application manifest and Service Worker, the PWA becomes installable on mobile devices and desktops with offline support for local data viewing. Establishing a GitHub Actions workflow enables automated deployment to Cloudflare Pages on every code push. Finally, comprehensive setup documentation empowers any Gmail user to clone, configure, and host their own private instance.

---

## Scope of Work

1. **Web Application Manifest (`manifest.json`):**
    - Create a standard Web App Manifest file with metadata:
        - Application name: `step-tracker`
        - Short name: `Step Tracker`
        - Theme color and background color specifications
        - Display mode: `standalone` (hides browser URL bar when installed)
        - Application icons (192x192 and 512x512 PNG sizes)
    - Link `manifest.json` within the `<head>` of `index.html`.

2. **PWA Service Worker and Offline Caching:**
    - Implement `sw.js` (Service Worker) registered during application load.
    - Cache static core shell assets (`index.html`, CSS stylesheets, JS scripts, vendor libraries, icons) during Service Worker installation.
    - Implement a "Cache First, Network Fallback" strategy for static application assets to allow instant offline application loading.
    - Bypass Service Worker cache for external REST API calls (`https://www.googleapis.com/*`) to ensure fresh token authentication and data sync calls.

3. **Production Cloudflare Pages CI/CD Pipeline:**
    - Configure GitHub Actions deployment workflow (`.github/workflows/deploy.yml`).
    - Define execution trigger on `git push` to `main` branch.
    - Automate production `config.js` injection using GitHub Repository Secret `GOOGLE_CLIENT_ID`.
    - Deploy build output to Cloudflare Pages via `cloudflare/wrangler-action`.

4. **Comprehensive Setup & Cloning Documentation:**
    - Author a complete, beginner-friendly setup guide inside `README.md` covering:
        - Google Cloud Console OAuth Setup: Step-by-step walkthrough to create a free Google Cloud project, enable Fitness API and Drive API, configure OAuth Consent Screen, and generate a Client ID.
        - Authorized Origins Configuration: Registering `http://localhost:1981` (for local dev) and `https://<your-project>.pages.dev` (for Cloudflare hosting).
        - Local Configuration: Instructions for creating `config.local.js` from `config.example.js`.
        - Free Cloudflare Pages Deployment: Instructions for connecting a cloned GitHub repository to Cloudflare Pages and setting up GitHub Secrets (`CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `GOOGLE_CLIENT_ID`).

## Technical Notes and Schemas

### Service Worker Cache Strategy

| Resource Type | Matching Pattern | Caching Strategy | Offline Behavior |
| :--- | :--- | :--- | :--- |
| App Shell Assets | `*.html`, `*.css`, `*.js`, `manifest.json` | Cache First, Network Fallback | Serves cached files immediately |
| External CDNs | `unpkg.com/dexie`, `accounts.google.com/gsi` | Stale-While-Revalidate | Serves cached library, updates in background |
| Google REST APIs | `googleapis.com/fitness/*`, `googleapis.com/drive/*` | Network Only | Requires internet connection; fails gracefully if offline |

### GitHub Secrets Required for Cloudflare Pipeline

| Secret Key | Description |
| :--- | :--- |
| `GOOGLE_CLIENT_ID` | Production Google OAuth Client ID string |
| `CLOUDFLARE_API_TOKEN` | API Token generated in Cloudflare with Pages deployment permissions |
| `CLOUDFLARE_ACCOUNT_ID` | Cloudflare Account ID string |

## Acceptance Criteria (Definition of Done)

### Scenario 1: PWA Installation and Standalone Display
- **Given** the application loaded on Chrome or Safari via HTTPS or localhost,
- **When** viewing the browser address bar or menu,
- **Then** an "Install Step Tracker" prompt becomes available,
- **And** installing launches `step-tracker` as an isolated standalone desktop or mobile app window without browser navigation controls.

### Scenario 2: Offline Application Loading
- **Given** an installed PWA instance that has loaded successfully at least once,
- **When** network connectivity is disabled and the application is opened,
- **Then** the application shell, Dashboard, Calendar, Search Lab, and Spatial Map interfaces load cleanly from Service Worker cache,
- **And** local IndexedDB records remain fully viewable offline.

### Scenario 3: Automated Cloudflare Deployment Pipeline
- **When** code is pushed to the `main` branch on GitHub,
- **Then** the GitHub Action workflow executes automatically,
- **And** injects the production `GOOGLE_CLIENT_ID` into runtime config,
- **And** deploys the application successfully to Cloudflare Pages (`https://step-tracker.pages.dev`).

### Scenario 4: Setup Guide Documentation Verification
- **Given** a new user with a standard Gmail account who clones the repository,
- **When** following the instructions in `README.md`,
- **Then** they can successfully create a Google Client ID, configure `config.local.js`, run the app locally on port 1981, and deploy their own instance to Cloudflare Pages without encountering undocumented configuration blockers.
