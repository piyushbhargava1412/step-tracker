# ARCUS Story Specification: ST-008

## Story Metadata
- **Story ID:** ST-008
- **Story Title:** Search Lab: Behavioral Insights and Comparative Analytics
- **Epic:** Analytics and Data Utility
- **App Name:** step-tracker
- **Target Local Environment:** http://localhost:1981
- **Primary Test Target:** Computation and rendering of behavioral insight modules (Near-Miss Detector, Day-of-Week Slump Analyzer, and Side-by-Side Range Comparison Engine).

---

## User Story Statement
> **As a** user seeking to improve my walking habits,  
> **I want** automated behavioral insights into near-misses, day-of-week slump patterns, and period-over-period comparisons,  
> **So that** I can identify structural routine weaknesses and measure performance progress across custom timeframes.

---

## Context and Business Value
Beyond raw search queries, users benefit from algorithmic analysis of behavioral patterns. Near-miss days (where walking target was 90-99% achieved) pinpoint potential candidates for manual treadmill overrides or missed phone syncs. Day-of-week slump analysis exposes structural habit gaps (for example, consistently missing targets on Sundays). Side-by-side date comparison provides quantifiable proof of progress over time.

---

## Scope of Work

1. **Near-Miss Detector Module:**
    - Provide a "Near-Miss Detector" pre-configured action filter inside the Search Lab tab.
    - Filter `daily_records` for entries where `effective_distance_km` reached between 90.0% and 99.9% of that day's active commitment target (`0.90 <= (effective_distance_km / target_distance_km) < 1.00`).
    - Render results in a dedicated summary list highlighting remaining steps/meters needed for each near-miss date, with an inline shortcut button to trigger the manual override drawer for review.

2. **Day-of-Week Slump Analyzer Module:**
    - Group all historical records (or records within a selected search window) by day of the week (Monday through Sunday).
    - Calculate summary metrics for each of the 7 days:
        - Target Hit Rate Percentage (`(Target Met Days / Total Days) * 100`)
        - Average Daily Steps
        - Total Cumulative Distance (km)
    - Identify and highlight the lowest-performing day of the week as the "Primary Slump Day".

3. **Side-by-Side Date Range Comparison Engine:**
    - Provide a dual date range selector interface allowing inputs for:
        - Period A (Start Date A to End Date A, e.g., "June 2025")
        - Period B (Start Date B to End Date B, e.g., "June 2026")
    - Calculate and display comparative metrics side-by-side:
        - Total Distance (km)
        - Average Daily Steps
        - Overall Commitment Hit Rate (%)
    - Calculate percentage delta values for each metric (`((Metric_B - Metric_A) / Metric_A) * 100`) with visual directional indicators (increase / decrease).

4. **Documentation Updates:**
    - Update repository documentation explaining near-miss criteria, day-of-week grouping logic, comparison formulas, and behavioral insight interpretations.

## Technical Notes and Schemas

### Near-Miss Filter Rule
A record `R` is classified as a Near-Miss if:
- `R.effective_distance_km >= (G(R.date) * 0.90)` AND `R.effective_distance_km < G(R.date)`, where `G(R.date)` is the effective goal target for that date.

### Day-of-Week Indexing Standard
Day grouping maps JavaScript Date index `0..6` to Monday..Sunday:
- Index 0: Monday
- Index 1: Tuesday
- Index 2: Wednesday
- Index 3: Thursday
- Index 4: Friday
- Index 5: Saturday
- Index 6: Sunday

### Comparison Delta Formula
`Delta_Percentage = Math.round(( (Value_Period_B - Value_Period_A) / Value_Period_A ) * 1000) / 10`

## Acceptance Criteria (Definition of Done)

### Scenario 1: Executing Near-Miss Detection
- **Given** historical records including a day with 4,750 steps against a 5,000-step goal (95% completion),
- **When** the user activates the Near-Miss Detector in Search Lab,
- **Then** the result set includes that date and displays "250 steps remaining (~190 meters)",
- **And** provides an action trigger to inspect or edit that date in the Day Detail Drawer.

### Scenario 2: Computing Day-of-Week Slump Analysis
- **Given** historical data spanning several months where Sunday target hit rate is 45% while Monday-Saturday hit rates exceed 90%,
- **When** viewing the Day-of-Week Slump Analyzer card,
- **Then** Sunday is designated and rendered as the "Primary Slump Day",
- **And** accurate hit rate percentages are rendered for all 7 days of the week.

### Scenario 3: Executing Side-by-Side Range Comparison
- **Given** Period A with 100 km total distance and Period B with 130 km total distance,
- **When** the user submits Period A and Period B for comparison,
- **Then** the comparative card displays Period A metrics, Period B metrics, and a calculated delta output of `+30.0%`.

### Scenario 4: Technical Documentation Update
- **Given** completion of the behavioral analytics module,
- **When** reviewing repository documentation,
- **Then** near-miss thresholds, slump calculation rules, and range comparison delta logic are accurately documented.
