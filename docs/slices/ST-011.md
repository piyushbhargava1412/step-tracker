# ARCUS Story Specification: ST-011

## Story Metadata
- **Story ID:** ST-011
- **Story Title:** Real-World Journeys and Automated Trophy Badges
- **Epic:** Gamification and Lifetime Milestones
- **App Name:** step-tracker
- **Target Local Environment:** http://localhost:1981
- **Primary Test Target:** Computation of cumulative lifetime distance conversions into virtual real-world journeys (Delhi to London) and automated unlock evaluation for milestone trophy badges.

---

## User Story Statement
> **As a** long-term user tracking my daily walks,  
> **I want** my total cumulative distance converted into real-world geographic journeys and unlockable achievement badges,  
> **So that** my daily effort is framed as an epic long-term adventure with clear celebratory milestones.

---

## Context and Business Value
Raw step totals can feel abstract over multi-month or multi-year periods. By converting total lifetime distance into iconic real-world routes (such as walking from Delhi to London, spanning approximately 6,700 km) and awarding dynamic achievement badges based on specific physical milestones, the application provides long-term intrinsic rewards that drive sustained app engagement.

---

## Scope of Work

1. **Cumulative Distance and Real-World Journey Engine:**
    - Calculate total cumulative effective distance (sum of `effective_distance_km` across all historical records in Dexie.js `daily_records`).
    - Define a primary journey target: "Delhi to London" with a target distance of 6,700 km.
    - Calculate percentage completion (`(cumulative_km / 6700) * 100`) and remaining distance.
    - Define virtual city route checkpoints along the path:
        - Checkpoint 1: Delhi, India (0 km)
        - Checkpoint 2: Tashkent, Uzbekistan (1,600 km)
        - Checkpoint 3: Istanbul, Turkey (4,500 km)
        - Checkpoint 4: Vienna, Austria (5,800 km)
        - Checkpoint 5: London, United Kingdom (6,700 km)
    - Determine current active segment and next upcoming virtual city checkpoint based on cumulative distance.

2. **Automated Trophy Evaluation Engine:**
    - Evaluate database state against specific achievement rules on application load and sync events:
        - Trophy A (Century Club): Lifetime days with `effective_distance_km >= 5.0 km` reaches 100 days.
        - Trophy B (Titan Day): At least 1 single daily record where `effective_distance_km >= 20.0 km`.
        - Trophy C (Iron Will): Maintained a commitment target hit rate `>= 95.0%` for 3 consecutive calendar months.
        - Trophy D (Everest Climber): Cumulative lifetime steps reach 116,000 steps (equivalent step count to scaling Mt. Everest elevation gain).
    - Compute progress percentage towards locked trophies.

3. **Milestones and Trophies View UI Component:**
    - Add a Milestones section to the Dashboard tab (or dedicated sub-panel) displaying:
        - Delhi-to-London Progress Banner with a progress bar, current virtual location, next target city, and remaining distance.
        - Trophy Showcase Grid displaying all trophy badges in either Unlocked state (highlighted style with unlock timestamp) or Locked state (grayscale style with progress bar toward completion).

4. **Documentation Updates:**
    - Update repository documentation explaining journey checkpoint mapping, trophy unlock conditions, and milestone calculation logic.

## Acceptance Criteria (Definition of Done)

### Scenario 1: Delhi-to-London Progress Calculation
- **Given** a cumulative lifetime walking distance of 4,180 km in Dexie.js,
- **When** viewing the Dashboard Macro Stats section,
- **Then** the progress bar renders at 62.4% completion,
- **And** the UI indicates current location between Istanbul (4,500 km checkpoint) and displays remaining distance as 2,520 km to London.

### Scenario 2: Automated Trophy Unlock (Century Club)
- **Given** a user achieves their 100th day with effective distance >= 5.0 km following a sync or edit event,
- **When** trophy evaluation runs,
- **Then** the `century_club` trophy state changes from Locked to Unlocked,
- **And** records the unlock timestamp in the `settings` store.

### Scenario 3: Rendering Locked vs Unlocked Trophies
- **Given** a user who has unlocked Titan Day but not Everest Climber,
- **When** viewing the Trophy Showcase Grid,
- **Then** Titan Day renders in active highlighted style with its unlock date,
- **And** Everest Climber renders in locked style accompanied by a current progress indicator (e.g. "82,000 / 116,000 steps - 70%").

### Scenario 4: Technical Documentation Update
- **Given** completion of the journeys and trophies module,
- **When** reviewing repository documentation,
- **Then** journey checkpoint markers, trophy unlock rules, and progress formulas are accurately documented.
