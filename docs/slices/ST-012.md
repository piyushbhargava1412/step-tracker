# ARCUS Story Specification: ST-012

## Story Metadata
- **Story ID:** ST-012
- **Story Title:** Silent Google Drive AppData Auto-Sync and Recovery
- **Epic:** Data Persistence and Cloud Backup
- **App Name:** step-tracker
- **Target Local Environment:** http://localhost:1981
- **Primary Test Target:** Automated JSON database snapshot export to Google Drive hidden appDataFolder, automated state recovery on fresh database initialization, and manual import/export capabilities.

---

## User Story Statement
> **As a** privacy-conscious user running step-tracker,  
> **I want** my database automatically backed up to and restored from my private Google Drive AppData folder,  
> **So that** my fitness records, manual overrides, and preferences are protected against browser cache wipes without relying on external third-party servers.

---

## Context and Business Value
Because browser IndexedDB storage can be cleared if a user wipes browser data or switches devices, relying solely on local browser memory presents a data durability risk. This story integrates Google Drive's hidden `appDataFolder` API space. It creates a seamless, serverless cloud backup mechanism that silently pushes updated database snapshots on sync/edit events and automatically restores full history when opening the application on a new device or cleared browser.

---

## Scope of Work

1. **Google Drive AppData Scope Authorization:**
   - Extend Google OAuth request scopes in `ST-001` token client configuration to include `https://www.googleapis.com/auth/drive.appdata`.
   - Ensure permissions request clearly communicates isolated AppData folder access without requesting full access to user's main Google Drive files.

2. **Database Serialization and Backup Engine:**
   - Construct a database exporter utility that extracts all records from Dexie.js stores (`daily_records` and `settings`).
   - Package extracted tables into a standardized JSON payload structure including schema version metadata, export timestamp, and record counts.

3. **Silent Background Upload Trigger:**
   - Implement Google Drive REST API integration targeting `appDataFolder`.
   - On completion of step sync operations (`ST-002`) or manual record overrides (`ST-006`), convert the database to a JSON string and upload/overwrite file `step_tracker_backup.json` in `appDataFolder`.
   - Execute uploads asynchronously in the background without blocking UI interactions.

4. **Fresh Launch Recovery Protocol:**
   - On application startup, inspect IndexedDB state.
   - If local database contains 0 records AND active Google OAuth token is present, query Google Drive `appDataFolder` for `step_tracker_backup.json`.
   - If backup file exists on Google Drive, download payload, validate schema version, and execute bulk restoration into Dexie.js stores.
   - Display UI notification confirming automatic state restoration (for example: "Restored 365 daily records from Google Drive backup").

5. **Manual Data Import/Export Settings Interface:**
   - Add a Backup and Recovery section to the settings drawer/modal providing:
     - "Trigger Drive Backup Now" manual upload button with last backup timestamp display.
     - "Download Local Backup JSON" button for offline disk storage.
     - "Restore from File" file picker to manually restore database state from a local JSON file.

6. **Documentation Updates:**
   - Update repository documentation explaining Google Drive AppData architecture, backup privacy guarantees, restoration flows, and manual JSON file handling.

## Technical Notes and Schemas

### Google Drive REST API Specifications
- **Search File Endpoint:** `GET https://www.googleapis.com/drive/v3/files?spaces=appDataFolder`
- **Upload Endpoint:** `POST https://www.googleapis.com/upload/drive/v3/files?uploadType=multipart`
- **Target Filename:** `step_tracker_backup.json`
- **OAuth Scope required:** `https://www.googleapis.com/auth/drive.appdata`

### JSON Backup Payload Schema Standard

```json
{
  "version": 1,
  "app": "step-tracker",
  "exported_at": "2026-08-08T20:00:00.000Z",
  "data": {
    "daily_records": [],
    "settings": []
  }
}

```

## Explicit Out of Scope

* Syncing database state to custom cloud databases (Firebase, AWS DynamoDB, Supabase).
* Conflict resolution algorithms for simultaneous multi-device active editing (last write wins based on `exported_at` timestamp).
* Exporting raw SQLite or binary database files.

## Acceptance Criteria (Definition of Done)

### Scenario 1: Silent Cloud Backup on Data Modification

* **Given** an authenticated session with AppData scope authorized,
* **When** a user syncs steps or saves a manual override,
* **Then** the application serializes Dexie.js data and silently uploads `step_tracker_backup.json` to Google Drive `appDataFolder` in the background,
* **And** updates the "Last Backup Time" setting indicator.

### Scenario 2: Automated Recovery on Fresh Device or Browser Clear

* **Given** a user opens `http://localhost:1981` on a new browser where IndexedDB is empty,
* **When** the user completes Google OAuth login,
* **Then** the application detects 0 local records, queries Google Drive `appDataFolder`, downloads `step_tracker_backup.json`, and populates Dexie.js,
* **And** the UI immediately renders historical streaks, calendar entries, and settings.

### Scenario 3: Manual JSON File Backup and Restoration

* **Given** an active database instance,
* **When** the user clicks "Download Local Backup JSON",
* **Then** a valid JSON file matching the backup schema is downloaded to the user's local disk,
* **And** uploading that file on another instance successfully restores all daily records and overrides.

### Scenario 4: Technical Documentation Update

* **Given** completion of the Google Drive AppData sync module,
* **When** reviewing repository documentation,
* **Then** AppData security rules, backup triggers, and restore logic are accurately documented.
