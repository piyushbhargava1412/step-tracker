# ARCUS Story Specification: ST-012 (Refined & Expanded)

## Story Metadata
- **Story ID:** ST-012
- **Story Title:** Data Loss Prevention: Local JSON Backup/Restore and Google Drive AppData Cloud Sync
- **Epic:** Data Resilience, Portability, and Storage Protection
- **App Name:** step-tracker
- **Target Local Environment:** http://localhost:1981
- **Primary Test Target:** Local JSON export/import pipeline, interactive storage persistence badge, silent background sync to Google Drive AppData folder, and 1-click cloud recovery on clean installs.

---

## User Story Statement
> **As a** health tracker user,  
> **I want** to back up and restore my entire step tracking database locally via JSON or silently via Google Drive AppData,  
> **So that** I am 100% immune to browser storage eviction, device changes, or accidental data wipes.

---

## Context and Business Value
Browsers treat IndexedDB as best-effort storage by default, reserving the right to silently clear data under disk pressure or following inactivity (e.g., iOS Safari's 7-day eviction rule). `ST-012` equips `step-tracker` with a multi-layered defense system:

1. **Active Persistence Promotion:** Turning the `#db-status` badge into an interactive trigger that prompts PWA installation or re-requests `navigator.storage.persist()`.
2. **Local JSON Backup & Restore:** Allowing users to download or upload complete, versioned snapshots of their Dexie IndexedDB state (including settings, overrides, and compressed screenshot proof blobs).
3. **Google Drive AppData Silent Cloud Backup:** Reusing the existing Google OAuth token to silently sync backups to the user's private, hidden `appDataFolder` in Google Drive with zero server costs and zero UI clutter.

---

## Scope of Work

1. **Interactive Storage Persistence Header Badge:**
   - Make the `#db-status` header badge clickable when displaying `⚠️ Storage not persisted`.
   - On click, open a guidance modal explaining browser eviction risks, providing steps to "Add to Home Screen" (PWA install), and offering a `[ Request Persistent Storage ]` button that re-executes `navigator.storage.persist()`.

2. **Local JSON Export & Import Engine:**
   - **Export Pipeline:**
     - Query all records from Dexie object stores (`daily_records` and `settings`).
     - Serialize records into a versioned JSON payload (`schema_version: 1`).
     - Convert compressed screenshot proof `Blob` objects into Base64 strings for portable JSON serialization.
     - Trigger a browser download with filename format: `step-tracker-backup-YYYY-MM-DD.json`.
   - **Import Pipeline:**
     - Provide a file picker input accepting `.json` files in the Settings modal.
     - Validate payload structure and schema version before executing writes.
     - Convert Base64 strings back into binary `Blob` objects for `daily_records` override records.
     - Execute a bulk Dexie transaction writing imported records to IndexedDB.
     - Re-render all application views (Dashboard, Calendar, Heatmap) immediately upon import completion.

3. **Google Drive AppData Silent Cloud Backup:**
   - Utilize the existing Google OAuth 2.0 access token with the authorized `https://www.googleapis.com/auth/drive.appdata` scope.
   - **Silent Upload Trigger:** Following every successful step sync in `steps.js`, serialize the current database state and push it in the background to `appDataFolder/step_tracker_backup.json` using Google Drive REST API v3:
     - Check if `step_tracker_backup.json` exists in `appDataFolder`.
     - Update (`PATCH`) if present, or create (`POST`) if absent.
   - Fail quietly in the background without interrupting the primary UI flow if the network is degraded.

4. **Cloud Auto-Recovery on Clean Installation:**
   - Upon application launch with an empty Dexie `daily_records` store, if a user connects their Google Account:
     - Query `appDataFolder` for `step_tracker_backup.json`.
     - If found, prompt the user with a recovery banner:  
       `☁️ Cloud backup found from [Backup Date]. [ Restore Cloud Backup ] [ Start Fresh ]`.
     - Clicking **Restore** populates Dexie IndexedDB and updates settings seamlessly.

## Technical Notes and Schemas

### Export/Import JSON Schema Standard (`schema_version: 1`)

```json
{
  "app_name": "step-tracker",
  "schema_version": 1,
  "exported_at": "2026-08-13T10:00:00.000Z",
  "settings": [
    { "key": "sync_anchor_date", "value": "2018-01-01" },
    { "key": "active_challenge", "value": { "start_date": "2026-08-01", "end_date": "2026-08-31" } }
  ],
  "daily_records": [
    {
      "date": "2026-08-11",
      "original_steps": 10585,
      "original_distance_km": 8.065,
      "effective_steps": 11900,
      "effective_distance_km": 9.067,
      "is_overridden": true,
      "synced_at": "2026-08-11T20:00:00.000Z",
      "override": {
        "effective_steps": 11900,
        "reason": "Samsung Watch Gap",
        "updated_at": "2026-08-11T20:05:00.000Z",
        "proof_image_base64": "data:image/webp;base64,UklGRi4AAABXRUJQVlA4..."
      }
    }
  ]
}

```

### Google Drive AppData API Query Reference

* **Search Existing Backup:**
```text
GET [https://www.googleapis.com/drive/v3/files?spaces=appDataFolder&q=name='step_tracker_backup.json](https://www.googleapis.com/drive/v3/files?spaces=appDataFolder&q=name='step_tracker_backup.json)'

```


* **Upload/Update Backup File:**
```text
PATCH/POST [https://www.googleapis.com/upload/drive/v3/files/](https://www.googleapis.com/upload/drive/v3/files/){fileId}?uploadType=media&spaces=appDataFolder

```

## Explicit Out of Scope

* Public Google Drive file sharing or multi-account sync.
* Multi-device real-time state conflict resolution (last-uploaded cloud backup wins).

---

## Assumptions

* The Google OAuth Client ID has `https://www.googleapis.com/auth/drive.appdata` enabled in Google Cloud Console.
* Dexie `settings` and `daily_records` object stores exist and are accessible.

---

## Acceptance Criteria (Definition of Done)

### Scenario 1: Interactive Storage Persistence Badge

* **Given** the header badge displays `⚠️ Storage not persisted`,
* **When** the user clicks the badge,
* **Then** a guidance modal appears explaining PWA installation,
* **And** clicking `[ Request Persistent Storage ]` re-triggers `navigator.storage.persist()`.

### Scenario 2: Manual Local JSON Export

* **Given** populated step records and settings in Dexie,
* **When** the user clicks "Export Local Backup" in the Settings panel,
* **Then** a structured `step-tracker-backup-YYYY-MM-DD.json` file is generated and downloaded,
* **And** all screenshot proof blobs are accurately encoded as Base64 strings.

### Scenario 3: Manual Local JSON Import

* **Given** a valid backup JSON file,
* **When** the user selects the file in the Import setting input,
* **Then** the JSON payload is validated, Base64 strings are converted back to Blobs,
* **And** Dexie IndexedDB is updated with all imported records and settings.

### Scenario 4: Silent Background Sync to Google Drive

* **Given** an authenticated user with Google Fit connected,
* **When** `steps.js` completes a step sync operation,
* **Then** a background job serializes Dexie and uploads `step_tracker_backup.json` to Google Drive `appDataFolder` without blocking the main UI thread.

### Scenario 5: Automatic Cloud Recovery

* **Given** a new device or cleared browser state with 0 records in Dexie,
* **When** the user connects their Google Account,
* **Then** the app detects the existing Drive AppData backup file and prompts the user to restore their complete history with 1 click.
