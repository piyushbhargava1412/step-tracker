# ARCUS Story Specification: ST-007

## Story Metadata
- **Story ID:** ST-007
- **Story Title:** Search Lab: Dynamic Query Engine and CSV Exporter
- **Epic:** Analytics and Data Utility
- **App Name:** step-tracker
- **Target Local Environment:** http://localhost:1981
- **Primary Test Target:** Execution of dynamic custom queries against Dexie.js daily records, summary stat calculation on query result sets, and client-side CSV/JSON file generation.

---

## User Story Statement
> **As a** data-driven user,  
> **I want** to search and filter my historical walking data using custom numerical and date criteria and export the results,  
> **So that** I can analyze specific activity subsets and download formatted datasets for personal record-keeping.

---

## Context and Business Value
While fixed dashboards and calendar views show predefined metrics, users often have unique analytical questions (for example: "How many days did I walk more than 8 km in 2025?" or "List all days where I submitted manual overrides"). This story implements the baseline Search Lab query engine and client-side data exporter, transforming raw IndexedDB entries into an interactive, exportable analytics suite.

---

## Scope of Work

1. **Custom Query Builder UI:**
   - Construct a multi-filter input panel on the Search Lab tab with options for:
     - Date Range Picker (Start Date and End Date; defaults to All-Time if unspecified).
     - Minimum Step Count (`Steps >= X`).
     - Maximum Step Count (`Steps <= Y`).
     - Minimum Distance (`Distance >= X` in km).
     - Manual Override Filter (All Records, Overridden Records Only, Non-Overridden Records Only).
     - Target Outcome Filter (All Records, Target Met Only, Target Missed Only).
   - Provide "Execute Search" and "Reset Filters" action controls.

2. **Query Execution Engine:**
   - Execute indexed queries against Dexie.js `daily_records` using compound filter conditions.
   - Filter records against `effective_steps` and `effective_distance_km` fields.
   - Return sorted results array ordered chronologically (newest to oldest).

3. **Query Results Data Grid:**
   - Render a scannable table listing matched records:
     - Date (`YYYY-MM-DD`)
     - Effective Steps
     - Effective Distance (km)
     - Goal Target Status (Met / Missed)
     - Override Status (displays note preview if present)

4. **Dynamic Result Set Summary Card:**
   - Calculate and display aggregated statistics for the current query result set:
     - Total Days Matched (`count`)
     - Match Percentage (`(matched_days / total_days_in_range) * 100`)
     - Cumulative Distance (sum of `effective_distance_km` in result set)
     - Average Daily Steps in Result Set

5. **Client-Side CSV/JSON Exporter Utility:**
   - Provide "Export to CSV" and "Export to JSON" action triggers on the search results view.
   - Generate formatted CSV data containing headers (`Date`, `Original_Steps`, `Original_Distance_KM`, `Effective_Steps`, `Effective_Distance_KM`, `Is_Overridden`, `Override_Note`).
   - Trigger browser client-side file download without transmitting data to external servers (filename format: `step-tracker-export-YYYY-MM-DD.csv`).

6. **Documentation Updates:**
   - Update repository documentation explaining query builder operations, export format specifications, and data filtering logic.

---

## Technical Notes and Schemas

### Filter Matrix Logic
A record `R` matches the query if and only if all active non-empty constraints are satisfied:
- `R.date >= StartDate` AND `R.date <= EndDate`
- `R.effective_steps >= MinSteps` AND `R.effective_steps <= MaxSteps`
- `R.effective_distance_km >= MinDistance`
- If Override Filter is "Overridden Only": `R.is_overridden == true`
- If Target Filter is "Met Only": `R.effective_distance_km >= TargetForDate`

### Export CSV Schema Standard
`Date,Original_Steps,Original_Distance_KM,Effective_Steps,Effective_Distance_KM,Is_Overridden,Override_Note`

## Acceptance Criteria (Definition of Done)

### Scenario 1: Multi-Criteria Query Execution
- **Given** a populated historical database in Dexie.js,
- **When** the user inputs `Distance >= 7.5 km` and selects `Target Met Only`,
- **Then** the result table displays only days meeting both criteria,
- **And** the summary card correctly updates matched days, cumulative distance, and average steps.

### Scenario 2: Overridden Record Filtering
- **Given** historical records containing both raw synced data and manual edits,
- **When** the user selects the `Overridden Records Only` filter,
- **Then** the search grid displays exclusively entries where `is_overridden == true`.

### Scenario 3: Client-Side CSV Export Generation
- **Given** an active search query returning 45 matched records,
- **When** the user clicks "Export to CSV",
- **Then** the browser initiates a local file download named `step-tracker-export-YYYY-MM-DD.csv`,
- **And** opening the file reveals 45 data rows matching the exact query filter results with correct CSV headers.

### Scenario 4: Technical Documentation Update
- **Given** completion of the Search Lab query and export module,
- **When** reviewing repository documentation,
- **Then** query builder rules, summary calculation formulas, and CSV export structures are accurately documented.
