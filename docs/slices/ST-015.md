# ARCUS Story Specification: ST-015

## Story Metadata
- **Story ID:** ST-015
- **Story Title:** Sync Horizon Settings and Database Prune/Wipe Utility
- **Epic:** Settings and Data Management
- **App Name:** step-tracker
- **Target Local Environment:** http://localhost:1981
- **Primary Test Target:** Navigation header Settings modal UI, custom sync anchor persistence in Dexie, dynamic window resolution in `steps.js`, targeted date range pruning, and full database reset.

---

## User Story Statement
> **As a** long-time fitness tracker user,  
> **I want** to configure my historical sync start date and prune or wipe local Dexie records,  
> **So that** I can exclude years of inactive or zero-step data, reclaim local IndexedDB storage, and maintain a fast, relevant dataset.

---

## Context and Business Value
Prior to this story, `step-tracker` attempted to backfill Google Fit step data back to a hardcoded anchor date of `2013-01-01`. Users who began actively walking or tracking steps years later (e.g., 2018) end up fetching, processing, and storing thousands of empty or zero-step records. This inflates local IndexedDB storage, degrades search lab performance, and litters heatmaps with meaningless inactive years. 

`ST-015` introduces a centralized **⚙️ Settings & Data Hygiene** panel in the navigation header. It allows users to set a dynamic **Sync Horizon Start Date**, prune old records prior to that horizon, or execute a full database wipe for a clean-slate reset.

---

## Scope of Work

1. **Header Settings Control & Drawer Integration:**
   - Add a compact `⚙️ Settings` button to the right side of the main header bar after the Sync Steps button.
   - Design a responsive Settings Modal / Slide-out Drawer overlay accessible from any application view.

2. **Dynamic Sync Horizon Configuration:**
   - Implement a **Track History From** date picker input (`<input type="date">`).
   - Default the initial sync anchor date to `2018-01-01` if unset.
   - Persist the selected date string (`YYYY-MM-DD`) in the Dexie `settings` store under the key `sync_anchor_date`.
   - Update `steps.js` -> `_determineSyncWindows()` to dynamically query `sync_anchor_date` from the `settings` store instead of referencing a hardcoded 2013 date constant.

3. **Data Impact Counter & Targeted Pruning Engine:**
   - On date picker change, query Dexie to calculate how many `daily_records` rows exist prior to the chosen sync horizon date (`date < sync_anchor_date`).
   - Render a dynamic impact preview text line (e.g., `"1,420 records found prior to 2018-01-01"`).
   - Implement a `🗑️ Prune Old Data` action button that executes a targeted bulk deletion:
     ```javascript
     await db.daily_records.where('date').below(targetDate).delete();
     ```
   - Prompt an inline confirmation step before executing the deletion to prevent accidental data loss.

4. **Full Database Reset / Wipe Utility:**
   - Include a **"Clear All Local Data (Wipe entire database)"** toggle checkbox in the settings panel.
   - **When Checked:**
     - Visually disable the date picker input (`opacity-50 pointer-events-none`).
     - Update the impact preview label to show total records in the database (e.g., `"All 3,120 local records will be deleted"`).
     - Switch the action button style to high-visibility hazard state: `🔥 Clear Entire Database`.
   - **On Execution:**
     - Wipe all records in `daily_records` via `db.daily_records.clear()`.
     - Delete the backfill latch key `initial_backfill_complete` from `settings` via `db.settings.delete('initial_backfill_complete')`.
     - Reset `sync_anchor_date` back to `2018-01-01`.

5. **UI Reactivity & Store Synchronization:**
   - Trigger immediate re-renders across Dashboard metrics, Active Streaks, Search Lab, and Heatmap components following a prune or wipe operation without requiring a browser page refresh.

## Explicit Out of Scope

* Deleting or wiping data directly from Google Fit Cloud servers (operation remains 100% local to Dexie IndexedDB).
* Automated scheduled database pruning routines (pruning is executed strictly on user demand).

* ST-001 through ST-006 are fully integrated.

## Acceptance Criteria (Definition of Done)

### Scenario 1: Configurable Sync Horizon

* **Given** the user opens the ⚙️ Settings menu,
* **When** they select a new start date of `2018-01-01` and click save,
* **Then** `sync_anchor_date` is saved to the Dexie `settings` store,
* **And** subsequent step sync requests stop fetching chunks once they reach `2018-01-01`.

### Scenario 2: Dynamic Impact Preview Calculation

* **Given** local step records spanning from `2013-01-01` through `2026-08-13`,
* **When** the user changes the date picker in Settings to `2020-01-01`,
* **Then** the impact preview text dynamically updates to display the exact count of records dated prior to `2020-01-01`.

### Scenario 3: Partial Data Pruning

* **Given** stored records from 2013 to 2026,
* **When** the user clicks "Prune Data Before 2018-01-01" and confirms,
* **Then** all `daily_records` rows with `date < '2018-01-01'` are permanently deleted from Dexie,
* **And** records dated `2018-01-01` onward remain intact.

### Scenario 4: Full Database Reset (Clear All)

* **Given** the "Clear All Local Data" checkbox is checked in Settings,
* **When** the user clicks "Clear Entire Database" and confirms,
* **Then** all rows in `daily_records` are wiped,
* **And** `initial_backfill_complete` is removed from `settings` to allow a fresh future sync.

### Scenario 5: Dashboard Reactivity

* **Given** completion of a prune or wipe operation,
* **When** the Settings modal is closed,
* **Then** the Dashboard cards, heatmaps, streaks, and challenge trackers refresh instantly without a page reload.
